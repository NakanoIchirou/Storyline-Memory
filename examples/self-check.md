## 仍存在的问题

- 玩家批准：散列仅绑定内容，归档程序仍可自行提交。生产使用须由玩家或受控宿主负责提交；尚无独立批准权限实现。
- 历史修订：同 id、event_id 可覆盖原记录，缺少自动旧新差异与单独修订确认。版本可追溯不等于阻止误改。
- 时间覆盖：through 值缺非空与时间回退验证。本次说明修正没有宣称修复代码。
- 角色输入预算：role 导出所有 available 条目，长期可能膨胀。接入契约要求主 Agent 选取相关历程，但工具尚未实现预算筛选。
- 主观转换与读取隔离：依赖 LLM 与宿主，当前 Python 不执行转换、不隔离文件或会话。
- 语义实验：只有短虚构用例的自查及人工提取记录的机械测试。真实长 TXT、独立干净角色会话及同模型普通摘要对照尚未完成。
- 双格式：Markdown 与 JSON 不同步，使用时须选择单一正式记录来源。

这些问题属于后续实施与实验范围，不以文档规则替代代码能力。保留现有三层底座，优先补提交边界、历史改写提示、时间覆盖校验，再进行真实语义实验；重大架构扩展仍需玩家确认。
