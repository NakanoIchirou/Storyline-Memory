# 规整指令自查：重复日常不能覆盖未解决的失约

虚构小样本，作者助手按更新后的 Skill 自查，不是独立 LLM 提取实验。基于 initial.txt、batch-1.txt 与 batch-2.txt 的模拟获批历史，假定玩家又提交如下文本请求归档：

```text
T=3..5，Saki 每天在同一家店点同样的茶，Ren 也来了。
两人讨论天气和茶杯颜色。Saki 对旧失约仍未决定是否原谅。
T=6，Ren 提起桥边那次谈话：“我还欠你一个完整解释。”
Saki 想：我愿意继续听，但还没有核实他的说法。
两人约定明天再谈，谈话尚未发生。
```

处理时同时参考 batch-2.txt 中已经听到住院说法的阶段。该阶段是测试前置记录，不把新 TXT 未提诊断当成 Saki 获得诊断。

## 本批规整草案

- 宏观：无新增，不把喝茶写成城市变化。
- 个人客观：T=3..5 日常喝茶合为一句；T=6 在 appointment-explanation 下追加再谈约定，事件仍开放。不能因为中间聊了茶就把失约续接成新事件，也不能把明天再谈记成已经完成。
- Saki 主观：T=3..5 对失约无实质变化，不逐日新增三条未原谅。T=6 保留愿意继续听、尚未核实的边界，不升级为完全信任。
- 历史压缩候选：三天重复点茶可合并为一个时间范围。失约的等待、旧解释、心境缓和、新说法及未核实保留；不压成“Saki 与 Ren 已和好”。

事件新增进展不是主观变化的充分证据。本批心理状态无新增时可以不写第三层新记录；主 Agent 仍可从已有第三层形成下一段输入，不需要新增事实才能演绎。

## 下一段 Saki 输入候选

```text
Rule：只决定自己的言行，不替他人决定。
第三层：记得旧失约。此前视为不在乎，后来开始考虑也许有困难；听过 Ren 的住院解释但尚未核实，仍未决定原谅，愿意继续听。
当前场景：Ren 说仍欠你完整解释，两人约定明天再谈。
```

不加载三次点茶、茶杯颜色或未知诊断。不加载不等于忘记；玩家要求保留的细节必须按其要求处理，不能用默认重要性自行删掉。

## 探针自查

| 问题 | 整理后的答案 |
| --- | --- |
| 是否知道具体诊断？ | 不知道，不传入诊断或管理侧来源 |
| 为什么还没有原谅？ | 未决定原谅、解释未核实；不擅自补心理原因 |
| 失约事件是否结束？ | 未结束，约定再谈不等于谈完 |
| 认知如何变化？ | 旧的确定解释 → 开始考虑其他可能 → 听到说法但未核实 |
| 三天日常是否必须三条？ | 不必，同状态可合并时间范围 |

这些输出证明本次用例自查可依指令完成，不证明泛化能力或几百万字历史可固定压成同样长度。Python 未新增自动压缩；已有 12 项机械测试仍只验证原有能力。
