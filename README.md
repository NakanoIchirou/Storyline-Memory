# Storyline Memory

**尽可能忠实保留时间轴上的轨迹，以及主客观事件梗概；不以保存具体细节为目标。**

保存长期语C轨迹与历程，并为角色判断提供连续的主观基础。上下文以内的短期记忆由大模型完成；正式档案由玩家主动归档、审核后提交。世界书和角色卡进入同一时间轴的前史，后续剧情沿相同结构延续。

保存的是“发生了什么、怎样发展、角色当时如何认识、后来如何变化”，不是逐句对话、逐个动作或场景描写。原文留作回查，Storyline 用梗概承接故事；事实、关系与认知转折不因省字而被改写。

Concept and design direction: **NakanoIchirou**. Prepared with Codex assistance, 2026-10-13.

## 核心：保存轨迹，逐步微缩细节

| 保留 | 默认不逐项归档 |
| --- | --- |
| 故事时间与关键节点顺序 | 每句对话和重复表达 |
| 事件起因的已知部分、进展与结果 | 动作、语气、服饰与环境描写 |
| 关系变化、承诺、未解决问题 | 无变化的日常互动 |
| 谁知道什么、怎样理解、理解怎样变化 | 模型可在当前场景自行完成的表现细节 |

具体细节只有影响事件身份、线索、因果、关系、后续判断，或玩家明确指定时才保留。例如某句话本身就是承诺或暗号，它便不只是描写细节。未明确的因果与心理不补写。

近期记录也用梗概，只在必要节点保持较细粒度。久远且低影响的连续片段合并为时间范围摘要，重要轨迹留下关键节点；不能把漫长认知变化压成“Saki 一直冷淡”，也不能把没有结束的冲突压成“双方已和好”。

## 三层之间是什么关系？

宏观历史与个人客观经历是故事现实中不同尺度的切面。个人主观则是：**此前主观所认知到的个人客观经历，在现在心境下形成的投影。**

```mermaid
flowchart TD
    W["世界设定、已确立历史与当前剧情"] --> A["主 Agent 整理客观切面"]
    A --> M["第一层：宏观客观历史"]
    A --> O["第二层：某角色个人客观经历"]
    O --> G["主 Agent：按角色已知与获准感知过滤、解释"]
    P["该角色此前第三层与当前心境"] --> G
    G --> S["下一段对话使用的第三层输入"]
    S --> B["该角色 subagent：判断、行动与回应"]
    R["适用 Rule 与获准当前场景"] --> B
```

箭头表示概念关系与信息边界，不是额外文件、叙事层或新增心理引擎。现实 W 是故事整体的比喻，不要求另建全知事件库。“切面”和“投影”也不是需要计算的几何运算。

**主 Agent 负责主观转换，角色 subagent 负责据此判断。** 客观事实可能在角色理解中产生偏差，客观档案本身不随之改变。各角色只收到自己的第三层、适用 Rule 和获准场景；Rule 中的隐藏设定也留在管理侧，不能绕过信息隔离。

第三层是认知与心路历程，不只是事实清单，也不是由主 Agent 预先决定角色动作的命令。详见[演绎接入契约与双角色用例](references/role-flow.md)。

| 层 | 保存什么 | 不意味着什么 |
| --- | --- | --- |
| 第一层：宏观客观历史 | 制度、社会、环境等世界变化及必要初始事实 | 不保存每个人的全部生活 |
| 第二层：个人客观经历 | 已确立的行动、互动、遭遇与关系事实 | 不因本人遗忘而删除，也不直接给角色读取 |
| 第三层：个人主观认知 | 已认知经历的记忆、信念、误解与当前理解，以及心理状态的历史 | 不从未知客观档案直接生成认知，不自动获得真相 |

第一层不是第二层的完整来源，私人事件可以只进入个人档案。三层都是有损摘要，未记载不等于未发生。

第三层有自身的连续历史。后来重新理解一件事，应追加或明确替代当前认知，保留“当时怎么想”的记录，不能改成“她一直这样想”。曾知但已遗忘的内容也不自动重新可用。

例如，Saki 只知道 Ren 没有赴约。她过去认为“他不在乎我”，现在心境缓和，改想“他也许遇到了困难”。**这是已知经历的重新解释，不是新事实。** Ren 当时住院的客观真相不能随心境变化自动进入她的认知；听到 Ren 的说法后，也应先记录“Ren 告诉我……”，不立即升级为核实事实。

## 世界书和角色卡归到哪里？

T=0 是玩家开始参与的锚点。以下选用用户提供的第四张图说明连续时间轴；它不包含前三层关系的旧画法：

![统一时间轴：三层前史与后续剧情连续](assets/diagrams/timeline.png)

| 初始素材 | T＜0 与开场状态的落位 | T≥0 如何延续 |
| --- | --- | --- |
| 世界书的历史、地理、制度和环境事实 | 第一层 | 追加获批的宏观变化 |
| 角色卡的身份、履历和客观关系 | 该角色第二层 | 追加实际经历 |
| 角色卡的记忆、信念、已知信息和心理状态 | 该角色第三层 | 新感知与对既有认知的重新理解 |
| 玩家控制权、生成约束和叙事风格 | Rules.md | 配置演绎与归档行为 |

T＜0 与 T≥0 使用相同记录结构。初始地理与心理状态可直接填写，不要求编造形成事件或童年创伤。旧世界书和角色卡可保留溯源，不再成为另一套并行权威。

## 玩家目录与仓库目录

每个故事独立保存：

```text
My-Story/
├── Rules.md                  # 作者规则，不是第一层
├── World-Storyline.md        # 第一层：宏观客观切面
└── Character/
    └── Saki/
        ├── Objective.md      # 第二层：个人客观切面
        └── Subjective.md     # 第三层：个人主观投影的历史
```

根目录的三个项目是文件布局，不对应三层编号。角色名单由玩家指定，不自动加入示例人物。生成模板：

```powershell
python scripts/init_workspace.py --root D:\CodexProject\My-Story --characters Saki
```

命令不覆盖已有文件，不填定设定，也不自动提交历史。Subjective.md 含历史认知及来源，角色仍须通过筛选后的认知包接收信息，不能直接读取整份文件或整个目录。

## 分清规则、配置与硬编码

Rules.md 是可编辑的作者规则配置；**写死在程序代码里的行为才叫硬编码。**

三层职责、权限、审核与整体回滚是机制。叙事语气、按场景分段和作者指定的不可变约束是运行规则。具体地名、时代、席位、人物关系和心理状态则是 Storyline 内容。

“目前有一百席议会”是世界事实；“作者规定席位永远不得改变”才是明确约束。不能自行把确定的初始设定变成永久规则，也不加入未经确认的权重、遗忘公式或数值人格参数。规则不成为第四条 Storyline。

## 从演绎到下一次使用

下面结合用户第二、三、五张图重述流程，并修正其中“三个并列投影”的说法：

```mermaid
flowchart TD
    R["主 Agent：规则与三层既有历史"] --> P["结合个人第二、第三层准备主观输入"]
    P --> C["角色 subagent：各自按 Rule 与第三层判断"]
    C --> X["主 Agent 接回回应与结果，模型维护当前上下文"]
    X --> N["继续演绎，不自动归档"]
    X --> T["玩家主动提交 TXT 请求归档"]
    T --> E["按场景、事件、故事时间提取增量"]
    E --> V["核查两个客观切面与主观认知变化"]
    V --> D["展示增量与必要决定"]
    D --> A["玩家审核批准"]
    A --> F["统一提交相关三层与操作状态"]
    F --> P
```

当前上下文是演绎现场，不是第四条持久 Storyline。流程循环不代表每轮归档。跨 TXT 保持事件标识，文件结束不代表事件完结。

下一段使用的第三层输入可随当前演绎发展，但不是每轮向 Subjective.md 或 JSON 快照写入。新感知无须先提交历史才能使用；玩家主动归档时再记录实际发生的变化。主 Agent 候选解释不自动成为正式历史。

归档检查点按故事时间补全受追踪角色的幕后候选，获批才提交；没有变化可以只更新覆盖时间。角色不逐轮后台运行。无冲突内容集中审核，事实自行查证，真正需要玩家选择的动机、补录和重大变化才提出问题。

## 规整历史，控制每次输入

每次玩家主动归档时，AI 按“不新增、追加、同事件合并进展、压缩候选、历史修订”整理本批涉及记录；不重写全部前史。重复日常可合并，关键转折、承诺、开放事件、来源及未知边界必须保留。第三层保留认知变化轨迹，不压成单一性格标签。历史压缩与差异仍须审核。

主 Agent 按当前场景从第三层选取相关历程与心境，不把所有 available 条目直接传给角色；不加载不等于遗忘。预算由玩家或宿主提供，无指定值时报告长度和取舍，不加入任意固定阈值。详见[规整指令](references/consolidation.md)及[重复日常与事件续接自查](examples/consolidation-trial.md)。

规整的核心是时间轴上的轨迹：越久远且越低影响的连续经历，越可合成紧凑的时间范围摘要；关键节点仍按先后保留。久远但仍影响当下的承诺、关系和认知转折不按年龄抹去。微缩档案不等于角色遗忘，不增加固定衰减公式或新层。

这些规则借鉴增量合并与按需读取，不增加永久记忆层。历史与旧版本仍可增长，不能保证无限剧情在无信息损失下固定总长度。Python 尚不执行自动压缩、记录删除或相关性预算筛选。

## 当前原型边界

Markdown 工作流以审核后的正文为正式记录，版本操作覆盖全部相关文件。可选 JSON 工具以获批快照为正式状态，Markdown 仅作标明版本的展示或待导入草稿。**当前没有 Markdown 与 JSON 自动同步，不能维护两套独立权威。**

工具不调用模型，不运行角色 Agent。`role` 只导出已提交的可用第三层记录，不完成第二层与第三层的主观转换，也不提供 Rule。演绎接入契约是宿主须实现的流程，不代表 Python 已有 Agent 运行时。批准散列防误提交，不证明玩家批准；角色包过滤不替代宿主文件、工具和会话隔离。Windows 工具保留本工程将数据放在 D 盘的约定，这不是三层模型的必要条件。

[本次自检与未解决问题](examples/self-check.md)区分说明修正与未实现的工程能力。

不扩展大世界模拟、Galgame 前端、人格引擎或自动监控。按需读取相关摘要，原文不常驻上下文。重大架构调整先征求玩家确认。

English: Preserve faithful chronological trajectories and concise objective and subjective event outlines, rather than scene-level detail. Older low-impact material can be compacted while preserving key transitions, unresolved events and knowledge boundaries.
