# 三层规整与上下文预算

这是归档侧 AI 的工作指令，不是自动整理引擎。只在玩家请求归档时提出永久记录变更；演绎时只准备相关输入。不会增加第四条 Storyline、另立永久当前状态库或自动遗忘算法。

## 归档操作

先读本批原文、相关记录与开放事件，保留独立来源。新增片段与旧记录对照，不把旧摘要当作新原文反复概括。

| 操作 | 适用情况 | 处理 |
| --- | --- | --- |
| 不新增 | 重复动作、同一状态无变化 | 保留旧记录，覆盖时间按实际处理范围更新 |
| 追加 | 新事件或新的认知转折 | 新记录，关联既有事件时沿用 event_id |
| 合并进展 | 同事件在跨 TXT 中延续 | 保留时间顺序、关键行动和开放问题，不按文件重建事件 |
| 压缩 | 已结束片段或无变化的重复描述 | 提出前后差异，保留转折、结果、来源与未知边界 |
| 历史修订 | 与旧事实不兼容 | 保留冲突证据，单独突出让玩家决定，不冒充文字压缩 |

按各层职责取舍，不在第一层重复每个人的生活。第二层不写心理猜测；第三层不因省字而丢掉从旧理解到新理解的轨迹。不同参与者的认知不混合，信念、他人说法和核实事实保持区别。

第三层无实质变化时不逐日新增“仍然相信”。重新解释时可以追加记录并标明替代关系；同一历程内的多个转折可在获批压缩中归纳，不能只留下最终结论。遗忘可以保留残留倾向，但不能给角色补上被遗忘的具体秘密或成因。

新可用摘要须保留角色仍记得的关键旧理解作为回顾，明确它不再是当前结论。否则将旧条目标成 available=false 后，role 导出只剩新结论，会丢失轨迹。若旧内容已经遗忘，则不能为保留轨迹而向角色恢复秘密；管理侧历史与角色当前可知历程分别处理。

压缩前后至少核对：事实与时间、事件标识与开放状态、关键承诺与关系、主观变化顺序、未知或未核实内容、来源和玩家保留细节。判断缺证据时保持留白；不能为了缩短而选择更确定的措辞。

## 持久档案与本次输入分开预算

历史量可能持续增长；预算主要限制每次审核和演绎输入。归档侧按涉及事件读取旧记录；主 Agent 为每名角色单独选取相关第三层，再完成主观转换。

角色输入优先保留适用规则、当前心境与关系基础、直接相关的关键历程、未完成承诺和问题、获准新感知及未知边界。无关的已结束经历不加载，需要时在管理侧补查。这些是阅读选择，不是角色自动遗忘；不能把“这次没加载”写成“角色忘记”。

输入不是单纯按最近时间截断。旧的承诺或认知转折可能比最近寒暄更重要。预算不足时先去重复和无关细节；关键内容仍放不下时展示可选省略范围或请求放宽预算，不默默丢掉影响当前判断的信息。没有玩家预算时报告长度并给出精炼草案，不承诺特定压缩率。

## 工具边界

Markdown 可在审核后合并正文，并由版本保留旧文。现有 JSON 工具支持同 id 的更新和追加，不支持删除记录、自动替代多条记录或压缩全部历史；第三层 available=false 只是读取筛选，不能当作归档删除。不要仅追加一条“总结”却仍把所有旧条目作为当前输入，或通过改写多条旧文为重复总结伪装压缩。

JSON 使用时可先由主 Agent 在不改档案的情况下整理当前输入；需要压缩正式记录且工具无法表达时明确报告限制，保留压缩提案供玩家选择。不能绕过工具篡改 HEAD 或悄悄换存储方案。批准散列不证明玩家批准，仍依赖玩家或受控宿主提交。

## 压缩探针与成本

对整理结果检查：实际发生了什么？角色自己知道什么？过去和现在的解释有何区别？谁作出了哪项承诺？哪些事件仍开放？角色包是否含隐藏真相？原文定位能否回查？不能仅凭摘要短或语义相似判定成功。

自然语言审核只展示本批变更、重要压缩差异及真正需要决定的问题，不逐条盘问重复信息。可报告操作数量、涉及事件、原文范围和输入字符数。有 Token 计量时再报告完整归档、读取、补查成本。当前没有长期压缩效果或 Token 节省的实证保证。
